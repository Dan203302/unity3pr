# SneakerShop Simulator

## 1. Название проекта (рабочее)

SneakerShop Simulator

---

## 2. Короткое описание / elevator pitch (1–2 предложения)

SneakerShop Simulator — это симулятор управления магазином кроссовок в жанре time-management, где игрок работает продавцом в торговом зале: обслуживает покупателей, подбирает им подходящие модели кроссовок и зарабатывает деньги на развитие магазина. Простая механика, яркие 3D-объекты и нарастающий поток клиентов создают динамичный и затягивающий игровой процесс.

## 4. Жанр и сеттинг

**Жанр:** симулятор / time-management / казуальный менеджмент.  
**Сеттинг:** современный торговый молл — светлый просторный зал с витринами, полками с кроссовками, кассой и примерочной зоной. Стиль — чистый, современный ритейл с яркими цветовыми акцентами брендов.

---

## 5. Игровой цикл (core loop)

Основной цикл взаимодействия игрока:

1. **Открытие магазина:** Игрок запускает рабочую смену — в зал начинают входить покупатели.
2. **Появление покупателя:** NPC-покупатель заходит в магазин и направляется к стойке; над ним отображается иконка желаемого типа кроссовок (цвет, стиль, размер).
3. **Выбор товара:** Игрок перемещается к нужной полке, берёт кроссовки и несёт покупателю.
4. **Примерка:** Покупатель «примеряет» товар. При правильном подборе — довольный эмодзи, при неправильном — отказ.
5. **Оплата:** Успешная продажа добавляет деньги в кассу.
6. **Управление запасами:** После нескольких продаж нужно пополнять полки из склада.
7. **Конец смены:** По истечении времени подсчитывается выручка, выдаётся оценка (1–3 звезды).
8. **Улучшения:** На заработанные деньги открываются новые модели кроссовок, расширяется ассортимент.
9. **Новая смена:** Сложность растёт — больше покупателей, сложнее запросы.

## 9. Требования к материалам

- **Шейдер:** URP/Lit (PBR) для всех 3D-объектов.
- **Карты:** Albedo (sRGB), Normal (Linear), Metallic/Smoothness (Linear), Ambient Occlusion.
- **Палитра:** Светлые, чистые тона (белый, серый, светло-бежевый) для помещения + яркие акценты (оранжевый, синий, зелёный) для брендинга кроссовок.
- **Атласы / Trim Sheets:** Элементы окружения (стены, пол, потолок) используют один тайловый материал. Мелкий реквизит объединён в атлас 2048×2048.
- **Утверждённые цветовые схемы:**
  - Основной цвет зала: `#F5F5F5` (почти белый)
  - Акцент 1 (витрины): `#FF6B35` (оранжевый)
  - Акцент 2 (бренд B): `#1A73E8` (синий)
  - Акцент 3 (бренд C): `#34A853` (зелёный)

## 11. Система загрузки/доставки контента

- **Core (встроенные в билд):** Основная сцена торгового зала, продавец-аватар, базовые кроссовки (3 модели), базовый NPC, UI, SFX.
- **Streaming (загрузка при старте сцены):** Дополнительные декорации зала, текстуры витрин, ambient-звуки.
- **OnDemand (через Addressables):** Новые модели кроссовок (DLC-контент), скины продавца, новые типы NPC, сезонные украшения магазина.

Система Addressables используется для группы `Remote_Assets`, содержащей контент обновлений. Профили: Dev, Staging, Release.

## 13. Целевая аудитория

**Описание:** Казуальные игроки 12–28 лет, интересующиеся модой, симуляторами и time-management играми. Основная аудитория — пользователи ПК и мобильных устройств, которые играют короткими сессиями (5–15 минут).

**Источники данных:**
- Анализ аналогов: Overcooked, Diner Dash, Supermarket Simulator — популярны у аудитории 14–30 лет.
- Тренды: симуляторы розничной торговли в Steam (Supermarket Simulator — 200k+ отзывов).
- Гипотезы: аудитория ценит простые правила, визуальную привлекательность, ощущение прогресса.

**Ключевые метрики:**
- Retention Day 1: ≥ 40%
- Средняя длительность сессии: 8–12 минут
- DAU/MAU: целевой показатель ≥ 0.15

## 14. План тестирования и критерии приёма ассета

**Визуальное тестирование:**
- Отсутствие швов, Z-fighting, чёрных пятен на мешах.
- Корректное отображение нормал-мап при освещении URP.
- LOD-переключения не дают резких «попингов» на расстоянии >5 м.

**Тестирование производительности:**
- Стабильные 60 FPS при 10 одновременных NPC на рекомендуемых настройках.
- Ассет не добавляет более 2 мс к frame time.
- Потребление VRAM не превышает выделенный бюджет.

**Функциональное тестирование:**
- Коллайдеры соответствуют визуальному мешу.
- LOD Group корректно переключается в зависимости от расстояния камеры.
- Prefab сохраняет все Override-настройки.

**Критерии приёма:**
- Все поля метаданных заполнены (ID, автор, лицензия).
- Конвенция именования соблюдена.
- Ассет добавлен в таблицу пула.

На первом этапе (Early Access) поддерживается только **русский язык** (основная аудитория).

## 17. Риски и альтернативы

| Риск | Вероятность | Альтернатива |
|---|---|---|
| Не найдены качественные 3D-модели кроссовок на Asset Store | Средняя | Использовать Unity Primitives + кастомные материалы для имитации |
| Высокая полигональность NPC снижает FPS | Средняя | Снизить количество одновременных NPC, aggressive LOD |
| Сложная анимационная система продавца выходит за рамки проекта | Высокая | Упростить до Root Motion + 2 анимации (Idle, Walk) |
| Addressables не работает в режиме симуляции | Низкая | Использовать Simulate Groups (Fast Mode) для отладки |
| Нет доступа к сети для Remote Assets | Низкая | Переключиться на Local Addressables группу для тестов |

## Practical 6 — Скрипты и логирование (SneakerShop)

В сцене **SneakerShop** созданы и прикреплены 5 C#-скриптов:

| Скрипт | Объект | Функция |
|---|---|---|
| StartLogger | Cafe_Shelf_1 | Логирует имя и позицию объекта при старте игры |
| CoordinateLogger | Main Camera | По нажатию **C** выводит текущие координаты камеры |
| CollisionReporter | PhysicsObject_Pract6 | Логирует OnCollisionEnter/Exit с указанием силы удара |
| TriggerReporter | TriggerZone_Pract6 | Логирует OnTriggerEnter/Exit — кто вошёл в зону |
| PhysicsImpulse | PhysicsObject_Pract6 | По нажатию **F** применяет импульс (AddForce) вверх |

**Используется New Input System** (Keyboard.current) вместо устаревшего Input.GetKeyDown.
